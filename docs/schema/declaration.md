# Declaring a schema

`#[derive(Table)]` turns one plain struct into the row type, a table handle, an insert struct and
a `&'static TableDef`. There is no separate schema file: the struct is the schema, and migrations
diff that metadata against a live database.

```rust
use besu::prelude::*;

#[derive(Table)]
#[besu(table = "users")]
pub struct User {
    #[besu(primary_key, auto_increment)] pub id: i64,
    #[besu(unique)] pub email: String,
    pub name: String,
}
```

## `table` (alias `name`)

The SQL table name; without it the struct name becomes `snake_case`. The handle identifier comes
from the table name, so `#[besu(table = "user_profiles")]` generates `user_profiles`.

## `schema`

PostgreSQL's schema, MySQL's database or SQLite's attached database; it qualifies every name and is
part of the table's identity, so `app.users` and `users` are two tables.

```rust
#[besu(table = "users", schema = "app")]     // CREATE TABLE "app"."users" (...)
```

Besu never runs `CREATE SCHEMA`. Leave it off for the default schema: PostgreSQL reports a table in
`current_schema()` as unqualified, so naming `public` makes the declared table look different.

## `column` (alias `name`)

The SQL column name; without it the field name is used verbatim.

```rust
#[besu(column = "email_address")]
pub email: String,      // "email_address" TEXT NOT NULL
```

## `primary_key` (alias `primary`)

One field is an inline `PRIMARY KEY`; two or more become a table-level constraint in declaration
order. A primary key column may not be nullable.

```rust
#[besu(primary_key)] pub user_id: i64,
#[besu(primary_key)] pub team_id: i64,
```

```sql
CREATE TABLE "memberships" ("user_id" BIGINT NOT NULL, "team_id" BIGINT NOT NULL,
    PRIMARY KEY ("user_id", "team_id"))
```

## `auto_increment` (alias `autoincrement`)

The database generates the value, which also removes the column from `users.insert(..)`.

```rust
#[besu(primary_key, auto_increment)]
pub id: i64,
```

| Dialect | Rendered |
| --- | --- |
| SQLite | `"id" INTEGER PRIMARY KEY AUTOINCREMENT` |
| PostgreSQL | `"id" BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| MySQL | `` `id` BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY `` |

SQLite ignores it unless the column is also the primary key, and MySQL requires an auto-increment
column to be a key.

## `unique`

A `UNIQUE` constraint on the column, rendered inline as `"email" TEXT NOT NULL UNIQUE`.

```rust
#[besu(unique)]
pub email: String,
```

MySQL cannot index `TEXT` or `BLOB` without a prefix, so it writes
`` UNIQUE KEY `email` (`email`(255)) ``: uniqueness over the first 255 characters only.

## `index`

A separate, non-unique, single-column index named `{table}_{column}_idx`.

```rust
#[besu(index)]
pub created_at: chrono::DateTime<chrono::Utc>,
// CREATE INDEX "users_created_at_idx" ON "users" ("created_at")
```

Composite and partial indexes have no attribute; see [indexes and constraints](indexes-constraints.md).

## Defaults: `default`, `default_now`, `default_sql`

A default makes the column optional in an insert; it does not change the Rust type, so the model
still holds `bool`, not `Option<bool>`.

```rust
#[besu(default = false)]
pub published: bool,                            // DEFAULT FALSE
#[besu(default = 0)]
pub views: i32,                                 // DEFAULT 0
#[besu(default_now)]
pub created_at: chrono::DateTime<chrono::Utc>,  // DEFAULT CURRENT_TIMESTAMP
#[besu(default_sql = "gen_random_uuid()")]
pub public_id: uuid::Uuid,                      // DEFAULT gen_random_uuid()
```

`default` takes a string, integer, float or boolean literal. `default_sql` is inserted verbatim and
is not checked. MySQL wraps a default on `TEXT`, `BLOB` or `JSON` in parentheses.

## `sql_type`

Names a `SqlType` implementation instead of inferring one from the field's type.

```rust
#[besu(sql_type = "besu::Decimal<10, 2>")]
pub amount: String,     // NUMERIC(10,2)
#[besu(sql_type = "besu::VarChar<64>")]
pub label: String,      // VARCHAR(64)
```

The field's Rust type must be that `SqlType`'s `Rust` type — `String` for `Decimal`, `Char` and
`VarChar`. A type of your own is a marker implementing `SqlType` plus `Decode` for each driver.

## `references`, `on_delete`, `on_update`

A single-column foreign key named `{table}_{column}_fkey`; `references` must be `"table.column"`
or `"schema.table.column"`, and a missing dot is a compile error.

```rust
#[besu(references = "users.id", on_delete = "cascade", on_update = "restrict")]
pub author_id: i64,
// CONSTRAINT "posts_author_id_fkey" FOREIGN KEY ("author_id")
//     REFERENCES "users" ("id") ON DELETE CASCADE ON UPDATE RESTRICT
```

Accepted actions are `cascade`, `set_null`/`setnull`, `set_default`/`setdefault`, `restrict` and
`no_action`/`noaction`; anything else falls back to no clause, so a typo is silent.

## `renamed_from`

Declares that the column had another name, so `push` renames it instead of dropping and adding it.
It produces no DDL in `CREATE TABLE`.

```rust
#[besu(column = "name", renamed_from = "full_name")]
pub name: String,       // ALTER TABLE "users" RENAME COLUMN "full_name" TO "name"
```

If no column by the old name exists, the declaration has nothing to match and the column is added.

## `skip`

Not a column at all: absent from the `SELECT` list, the insert struct and the `TableDef`. Decoding
fills it with `Default::default()`, so the field must implement `Default`.

```rust
#[besu(skip)]
pub cached_score: f64,
```

## What the derive generates

| Item | What it is |
| --- | --- |
| `User` | The row type, with `Decode<Dr>` implemented for every driver |
| `UserTable` | The handle's type, and the table's type-level identity |
| `users` | A `const` handle with one `Column` field per column |
| `UserInsert` | The insert struct, implementing `Insertable` |
| `users.def()` | The `&'static TableDef`; also `UserTable::DEF` |

There is no separate inferred-select type: the struct is what a `SELECT` returns. A column reference
carries its name, SQL type and nullability, and is `Copy`, so `users.id.name()` is `"id"` and
`users.id.type_def()` is `TypeDef::Int8`.

`UserInsert` stores every column as a `Set<T>`, which keeps "not provided" distinct from
"explicitly NULL", and has one setter per column. `From<User> for UserInsert` converts a whole model,
leaving the auto-increment column unset.

## Nullability

Nullability is a type parameter on `Column` (`Column<T, S, N = NonNull>`), not a wrapper around the
SQL type, so `Option` never nests: the derive strips exactly one `Option` and rejects the inner one,
making `Option<Option<T>>` a compile error. A primary key or auto-increment column may not be
nullable.

## What is checked

| Mistake | When it fails |
| --- | --- |
| A field type with no mapping (`char`, `f16`, an array) | Compile error listing the supported types |
| A generic, enum, union, tuple or unit-struct table | Compile error |
| A table whose every field is `skip`ped | Compile error |
| A nullable primary key or auto-increment column | Compile error |
| A malformed `references` string, or an unknown attribute key | Compile error |
| Two tables with the same SQL name in one module | Compile error at the generated handle |
| A database that drifted from the struct | Runtime, caught by `push` unless destructive |

## Gotchas

- The mapping looks at the last path segment, so a type alias or a same-named type from another
  crate can map to the wrong SQL type. `time::Date` is not `chrono::NaiveDate`.
- `DateTime` is matched by name, not by its full type. `chrono::DateTime<Local>` is declared
  `TimestampTz`, but no driver implements `Decode` for it. Use `DateTime<Utc>`.
- Two tables with the same SQL name in one module generate the same handle and collide.
- Generated names are fixed: `{table}_{column}_idx` and `{table}_{column}_fkey`. A hand-written
  index or constraint with the same name collides.
- A `UNIQUE` on a JSON column renders nothing on MySQL, because MySQL cannot index one.
- `#[besu(skip)]` removes the field from reading and writing. For a column the database fills in,
  use `default` or `auto_increment` instead.
- `default` accepts literals only. An expression is a compile error that points at `default_sql`.
