# Getting started

This page takes you from an empty crate to a table you can insert into and query, in about
fifty lines. It uses SQLite because it needs no server, but nothing in the query code is
SQLite-specific.

## Install

```toml
[dependencies]
besu = "0.1"
besu-sqlite = "0.1"
tokio = { version = "1", features = ["rt-multi-thread", "macros"] }
```

Three notes on features:

- `besu` enables `derive` and `migrate` by default. `derive` gives you `#[derive(Table)]`;
  `migrate` gives you `push`, `introspect`, `schema_snapshot` and `migrate`.
- `besu-sqlite` enables `sqlx` and `runtime-tokio` by default. Turn `sqlx` off only if you
  want the dialect and DDL without a driver.
- The `prelude` re-exports the builders, the expression helpers, the derive macro, `sql!`
  and the traits that make method syntax work.

## Define a table

A table is a plain struct. Field names become column names, Rust types become SQL types, and
`Option<T>` becomes a nullable column.

```rust
use besu::prelude::*;

#[derive(Table, Debug, Clone, PartialEq)]
#[besu(table = "users")]
pub struct User {
    /// Generated by the database, so `users.insert(..)` does not ask for it.
    #[besu(primary_key, auto_increment)]
    pub id: i64,
    #[besu(unique)]
    pub email: String,
    pub name: String,
    pub age: i32,
    pub bio: Option<String>,
}
```

The derive emits four things from that struct:

| Item | What it is |
| --- | --- |
| `User` | The row type, with `Decode` implemented for every driver |
| `users` | A `const` table handle whose fields are typed column references |
| `UserTable` | The handle's type, also used as the table's type-level identity |
| `UserInsert` | The insert struct returned by `users.insert(..)` |

So `users.age` is a `Column<UserTable, Int4, NonNull>`: it carries the column name, the SQL
type and the nullability, and copying it costs nothing.

## Connect

```rust
use besu_sqlite::Sqlx;

# async fn connect() -> Result<(), Box<dyn std::error::Error>> {
let db = besu::Database::new(Sqlx::memory().await?);
# Ok(())
# }
```

`Sqlx::new("app.db")` opens or creates a file with foreign keys enforced and WAL journalling;
`Sqlx::connect("sqlite::memory:")` parses a connection string; `Sqlx::memory()` is the
in-memory shorthand. `besu_sqlite::Database` is a type alias for `besu::Database<Sqlx>` if you
prefer the shorter name.

## Create the tables

The declared schema and the live schema are the same type, so creating tables is a one-liner.
`push` introspects first and applies only what is missing, which is why it is safe to run on
every boot.

```rust
# use besu::prelude::*;
# use besu_sqlite::Sqlx;
# #[derive(Table)] #[besu(table = "users")]
# struct User { #[besu(primary_key, auto_increment)] id: i64, name: String, age: i32, bio: Option<String> }
# async fn create() -> Result<(), Box<dyn std::error::Error>> {
# let db = besu::Database::new(Sqlx::memory().await?);
db.push([users.def()]).await?;
# Ok(())
# }
```

That needs the `migrate` feature. If you would rather write the DDL yourself, use raw SQL:

```rust
# use besu::prelude::*;
# use besu_sqlite::Sqlx;
# async fn create() -> Result<(), Box<dyn std::error::Error>> {
# let db = besu::Database::new(Sqlx::memory().await?);
db.execute(sql!(
    r#"CREATE TABLE "users" (
        "id" INTEGER PRIMARY KEY AUTOINCREMENT,
        "name" TEXT NOT NULL,
        "age" INTEGER NOT NULL,
        "bio" TEXT
    )"#
))
.await?;
# Ok(())
# }
```

## Insert and select

`users.insert(..)` takes exactly the columns the database cannot fill in: not the
auto-incrementing primary key, not nullable columns, and not columns with a default. Here that
is `email`, `name` and `age`, in declaration order.

```rust
# use besu::prelude::*;
# use besu_sqlite::Sqlx;
# #[derive(Table)] #[besu(table = "users")]
# struct User { #[besu(primary_key, auto_increment)] id: i64, #[besu(unique)] email: String, name: String, age: i32, bio: Option<String> }
# async fn insert() -> Result<(), Box<dyn std::error::Error>> {
# let db = besu::Database::new(Sqlx::memory().await?);
let created: Vec<User> = db
    .insert(users)
    .value(users.insert("oscar@example.com", "Oscar", 21))
    .returning(users)
    .await?;

let oscar = &created[0];
assert_eq!(oscar.name, "Oscar");
assert_eq!(oscar.bio, None);
# Ok(())
# }
```

`returning(users)` selects the whole row, including the generated id. Without it the insert
still runs and resolves to the driver's output (for SQLite, a `SqliteQueryResult`).

Selecting is the same shape:

```rust
# use besu::prelude::*;
# use besu_sqlite::Sqlx;
# #[derive(Table)] #[besu(table = "users")]
# struct User { #[besu(primary_key, auto_increment)] id: i64, name: String, age: i32, bio: Option<String> }
# async fn select() -> Result<(), Box<dyn std::error::Error>> {
# let db = besu::Database::new(Sqlx::memory().await?);
let adults: Vec<User> = db
    .select(users)
    .filter(users.age.gte(18))
    .order_by(users.name.asc())
    .limit(50)
    .await?;
# Ok(())
# }
```

That builds exactly:

```sql
SELECT "users"."id", "users"."name", "users"."age", "users"."bio"
FROM "users"
WHERE ("users"."age" >= ?)
ORDER BY "users"."name" ASC
LIMIT ?
```

You can check this yourself with no database at all:

```rust
use besu::prelude::*;

let db = besu::dry::<besu_sqlite::SQLite>();

let sql = db
    .select(users)
    .filter(users.age.gte(18))
    .to_sql()?;

assert!(sql.sql().contains(r#"WHERE ("users"."age" >= ?)"#));
# Ok::<(), besu::Error>(())
```

## The whole program

```rust
use besu::prelude::*;
use besu_sqlite::Sqlx;

#[derive(Table, Debug, Clone, PartialEq)]
#[besu(table = "users")]
pub struct User {
    #[besu(primary_key, auto_increment)]
    pub id: i64,
    #[besu(unique)]
    pub email: String,
    pub name: String,
    pub age: i32,
    pub bio: Option<String>,
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let db = besu::Database::new(Sqlx::memory().await?);

    // Idempotent: creates the table if it does not exist, does nothing otherwise.
    db.push([users.def()]).await?;

    let oscar = db
        .insert(users)
        .value(users.insert("oscar@example.com", "Oscar", 21))
        .returning(users)
        .await?
        .remove(0);

    db.insert(users)
        .value(users.insert("monty@example.com", "Monty", 7))
        .await?;

    let adults: Vec<User> = db
        .select(users)
        .filter(users.age.gte(18))
        .order_by(users.age.desc())
        .await?;

    assert_eq!(adults.len(), 1);
    assert_eq!(adults[0].id, oscar.id);

    db.update(users)
        .set(users.age, 22)
        .filter(users.id.eq(oscar.id))
        .await?;

    db.delete(users)
        .filter(users.id.eq(oscar.id))
        .await?;

    Ok(())
}
```

## Gotchas

- The handle comes from the *table* name, not the struct name. `#[besu(table = "users")]`
  generates `users`; a struct called `UserProfile` with no attribute generates
  `user_profile`.
- A table must be a struct with named fields and no generic parameters. Enums, tuples and
  unit structs are rejected at compile time.
- `push` is idempotent because it diffs first. `create_schema` is not: it emits
  `CREATE TABLE` for every table and fails if one already exists.
- Row decoding follows the column declaration order. Reordering fields changes the order of
  the `SELECT` list, which is why `SELECT *` written by hand still has to match the struct.
- The generated SQL uses the driver's placeholder spelling (`?` for SQLite and MySQL, `$1`
  for PostgreSQL), so the string in a test is dialect-specific even though the builder is not.
